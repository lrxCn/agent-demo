## 1. 设计原则

| # | 原则 | 落地表现 |
|---|---|---|
| 1 | **叠加而非重构** | 所有新增代码 / 表 / 接口都挂在三层各自的"common"或"observability"子目录下，不动 Phase 0–6 的业务模块（`student/` / `knowledge/` / `rtc/` 等） |
| 2 | **统一标识：W3C trace_id** | 三端共用 32 字符 hex `trace_id`，作为唯一关联键 |
| 3 | **职责单一：一层兜一层** | Agent 不解决的（鉴权、配额、审计落库）由 Backend 兜；Backend 不解决的（trace 生成、反馈采集）由 Frontend 兜 |
| 4 | **配置外置** | 阈值、模型名、黑名单文件路径全在 `.env` / `*.yaml`，不硬编码 |
| 5 | **零新增数据库** | `audit_logs` 表落 SQLite 现有连接；配额计数器复用现有 Redis；评估数据复用 LangSmith Dataset |
| 6 | **零新增基础设施** | 不引入 Prometheus / Grafana / Loki / OTel collector 等任何新进程 |
| 7 | **单点可替换** | 每个监控组件（trace 协议、guardrails、cost 计算、dataset）都可在不动其他组件的前提下替换（详见 `2.TECH_SELECTION.md` §10） |

## 3. 9 个 ★ 叠加点说明

> 编号与 §2 图中 P1~P9 一一对应。每条都给"在哪个文件 + 干什么 + 为什么放在这一层"。

### P1 — 前端 `traceparent` 生成与注入

- **文件**：`packages/frontend/src/api/request.ts`（修改 axios 拦截器）
- **行为**：每个 HTTP 请求 outbound 时调用 `generateTraceparent()`，写入 header `traceparent: 00-<32hex>-<16hex>-01`
- **辅助文件**：`packages/frontend/src/utils/trace.ts`（新增，约 20 行）
- **为什么放前端**：trace_id 的"起点"应当贴近用户交互瞬间（按下回车的那次 request 是同一个 trace_id 的开端），由后端生成会丢失"用户行为 ↔ 请求"的对应。

### P2 — 前端 SSE `{type:'trace'}` 解析

- **文件**：`packages/frontend/src/composables/useChat.ts`（修改 SSE 事件分支处理）
- **行为**：识别 SSE 流中 `{type:'trace', trace_id, langsmith_run_id}` 这种新事件，把 `langsmith_run_id` 挂到当前 `assistant` message 的 `meta.langsmith_run_id`
- **为什么放前端**：让 P3 的反馈按钮能拿到精确的 LangSmith run_id 关联到具体一次 trace，而不是按 thread 模糊匹配。

### P3 — 前端反馈按钮

- **文件**：`packages/frontend/src/components/chat/ChatBubble.vue`（修改：每条 AI 消息下挂三按钮）+ `packages/frontend/src/api/modules/agent.ts`（新增 `postFeedback` 方法）
- **行为**：用户点击 👍/👎/📝 → 调 `POST /api/v1/agent/feedback`，body 含 `{ thread_id, langsmith_run_id, feedback, comment? }`
- **为什么放前端**：反馈采集是前端职责（UI 交互），不能让后端定时拉。

### P4 — 后端全局 Trace 拦截器 + 结构化日志

- **文件**：
  - `packages/backend/src/common/interceptors/trace.interceptor.ts`（新增，约 50 行）
  - `packages/backend/src/common/middleware/structured-log.middleware.ts`（新增，约 60 行）
  - `packages/backend/src/common/context/trace-context.ts`（新增，封装 `AsyncLocalStorage`）
  - `packages/backend/src/app.module.ts`（修改：注册全局 provider）
- **行为**：
  1. 从 `traceparent` header 解出 `trace_id`，挂到 `AsyncLocalStorage`
  2. 替换所有 `Logger.log/warn/error` 调用：从上下文取 `trace_id` 自动注入 JSON 日志字段
- **为什么放后端**：所有后续 Service / DAO 调用都要能取到 `trace_id`，必须用 Node.js 原生 `async_hooks.AsyncLocalStorage` 在 NestJS 全局拦截器层注入。

### P5 — Token 配额 + 工具白名单（同源决策）

- **文件**：
  - `packages/backend/src/common/quota/quota.service.ts`（新增）
  - `packages/backend/src/common/quota/quota.module.ts`（新增）
  - `packages/backend/src/common/quota/tool-acl.service.ts`（新增）
  - `packages/backend/src/agent/agent.service.ts`（修改：调用 `quota.checkAndReserve` + 计算 `allowed_builtin_tools`）
  - `packages/agent/src/graph/state.py`（修改：新增 `allowed_builtin_tools` 字段）
  - `packages/agent/src/graph/nodes.py` `chat_node`（修改：按 `allowed_builtin_tools` 过滤 builtin 工具）
- **行为**：
  - 请求进入 `chatStream` 前 → 查 Redis 配额，超限抛 429
  - 同时按 `user.permissions` 计算 `allowed_builtin_tools` 数组传给 Agent
  - SSE 结束时从 LangGraph 最后一帧 metadata 取 `usage.total_tokens` 写回 Redis
- **为什么放后端 + Agent 双端**：配额必须在 Agent 之前拦截（避免烧 token），但工具白名单的"执行"必须在 Agent 内部生效（否则 LangGraph 还是会注入工具）。**这是"一层兜一层"原则的典型例子**。

### P6 — Feedback 接口 + Dataset 推送

- **文件**：
  - `packages/backend/src/agent/feedback.controller.ts`（新增）
  - `packages/backend/src/agent/feedback.service.ts`（新增）
  - `packages/backend/src/agent/agent.module.ts`（修改：注册 controller/service）
- **行为**：收到 `POST /api/v1/agent/feedback` → 调 LangSmith REST：
  1. `POST {LANGCHAIN_ENDPOINT}/runs/{run_id}/feedback`（打分）
  2. 若 `feedback=='down'`，额外 `POST {LANGCHAIN_ENDPOINT}/datasets/{dataset_id}/examples`（入 dataset）
- **为什么放后端**：要校验 `JwtAuthGuard` 权限、要从后端环境变量取 `LANGSMITH_API_KEY`（不能暴露给前端）。

### P6' — Eval CLI

- **文件**：
  - `packages/agent/src/eval/__init__.py`（新增）
  - `packages/agent/src/eval/runner.py`（新增，约 100 行）
  - `packages/agent/src/eval/evaluators/`（新增子目录）
    - `general_llm_judge.py`（LLM-as-judge，用 Kimi-K2.6）
    - `rag_ragas.py`（Ragas 评估器 wrapper）
    - `tool_match.py`（结构化对比）
  - `packages/agent/pyproject.toml`（修改：`[project.scripts] eval = "src.eval.runner:main"`）
  - 根 `package.json`（修改：`"eval:run": "cd packages/agent && uv run eval"`）
- **为什么放 Agent**：eval 跑分需要直接调 LangGraph（而不是经后端），用 LangSmith Python SDK 最直接。

### P7 — Guardrails（输入 + 输出 filter）

- **文件**：
  - `packages/agent/src/guardrails/__init__.py`（新增）
  - `packages/agent/src/guardrails/input_filter.py`（新增）
  - `packages/agent/src/guardrails/output_filter.py`（新增）
  - `packages/agent/src/guardrails/audit_client.py`（新增：HTTP 回写后端）
  - `packages/agent/guardrails/blacklist.yaml`（新增黑名单）
  - `packages/agent/guardrails/sensitive.yaml`（新增敏感词）
  - `packages/agent/src/graph/nodes.py` `chat_node`（修改：入口调 `input_filter`，return 前调 `output_filter`）
- **行为**：
  - 输入：命中黑名单 → 追加 `SystemMessage("⚠️ 用户输入命中安全规则…")` + 通过 `audit_client` HTTP 回写 audit 事件
  - 输出：正则替换 PII、扫敏感词 → 替换或追加脱敏提示 + 回写 audit
- **为什么放 Agent**：filter 必须紧贴 LLM 调用前后，前端 / 后端都拿不到完整的 LLM 输入 / 输出（content 是流式的）。

### P8 — Agent 端 LangSmith Metadata 主动打标

- **文件**：`packages/agent/src/graph/nodes.py` `chat_node`（修改：入口插入 4 行调用）
- **行为**：

```python
from langsmith.run_helpers import get_current_run_tree

run = get_current_run_tree()
if run is not None:
    run.add_metadata({
        'app_trace_id': state.get('app_trace_id', ''),
        'mem0_user_id': state.get('mem0_user_id', ''),
        'thread_id': state.get('thread_id', ''),
        'role_ids': state.get('user_role_ids', []),
    })
```

- **为什么放 Agent**：LangSmith 上"按业务维度切片"必须靠 metadata；前端 / 后端的 trace_id 与 LangSmith run_id 通过这个 metadata 字段在 LangSmith 上"焊死"。

### P9 — 审计日志落 SQLite

- **文件**：
  - `packages/backend/src/dao/sqlite/audit-log.entity.ts`（新增 TypeORM 实体）
  - `packages/backend/src/dao/sqlite/audit-log.dao.ts`（新增 DAO 实现）
  - `packages/backend/src/dao/interfaces/audit-log.dao.interface.ts`（新增接口）
  - `packages/backend/src/dao/dao.module.ts`（修改：注入 `IAuditLogDao` provider）
  - `packages/backend/src/agent/audit.controller.ts`（新增：内部接口 `POST /api/v1/internal/audit-log`，校验 `INTERNAL_API_KEY` header）
- **为什么放后端**：所有持久化必须经 DAO 层（项目铁律）；Agent 端只通过 HTTP 回写，不直接动 SQLite。

## 5. 关键数据流

### 5.1 正常对话的 trace 链路

> 对应 DoD-1（trace 闭环）。


## 6. trace_id 规范（W3C Trace Context）

### 6.1 格式

```
traceparent: 00-<32 hex trace_id>-<16 hex span_id>-01
                ─────────┬──────── ──────┬──────── ─┬
                         │               │          │
              一次 trace 唯一标识         │      flag, 01 表示采样
                                   一次 hop 的 span_id
```

例：`00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`

### 6.2 生成位置

| 位置 | 文件 | 时机 |
|---|---|---|
| 浏览器 | `packages/frontend/src/utils/trace.ts` | 每次 outbound HTTP 请求 |
| 浏览器（SSE） | `packages/frontend/src/composables/useChat.ts` | 调 fetch 时手动加 header |
| 后端（fallback） | `packages/backend/src/common/interceptors/trace.interceptor.ts` | header 缺失时 fallback 生成（记 `extra.trace_origin=backend`） |

### 6.3 透传位置

| 跳数 | 媒介 | 字段 |
|---|---|---|
| 1. Browser → Backend | HTTP header | `traceparent` |
| 2. Backend → Agent | LangGraph input body | `input.metadata.app_trace_id`（仅 32 hex 部分） |
| 3. Agent → LangSmith | LangSmith metadata | `metadata.app_trace_id` |
| 4. Backend → Browser（回流 run_id） | SSE event payload | `{type:'trace', trace_id, langsmith_run_id}` |
| 5. Agent → Backend（audit 回写） | HTTP body | `body.trace_id` + header `INTERNAL_API_KEY` |

### 6.4 跨进程一致性保证

- `trace_id` 在 1~5 跳中**保持 32 hex 字符串不变**
- `span_id` 可在每跳新生成（v1 简化处理：只关心 trace_id，不维护 span 树）
- LangSmith 内部的 run 树（chat_node → tool_node 等）由 LangChain SDK 自动维护，与本规范并行

## 9. 与现有架构的契合点

> 这些是"为什么这套监控体系能干净嵌入现有架构"的依据，便于代码评审时核对。

| 现有架构特性 | 监控体系如何复用 |
|---|---|
| **`.env` 集中配置 + dotenv 加载** | 监控所有阈值（配额、黑名单路径、INTERNAL_API_KEY）走 `.env` |
| **`LANGSMITH_API_KEY` 已预留** | 启用 LangSmith 零代码 |
| **DAO 抽象层** | `IAuditLogDao` 走同一模式，未来切换数据库无影响 |
| **`AppGateway` + `UserFrontendToolsService`** | 不动现有 WebSocket，audit 走 HTTP（避免污染 WS 通道） |
| **`@RequirePermissions` 装饰器** | 新增权限 `agent:feedback` `agent:tool:*` 复用现有 RBAC |
| **`SkipResponseWrap` 装饰器** | SSE 流跳过 `ResponseInterceptor`，新 `{type:'trace'}` payload 自然透传 |
| **`ToolRegistry` 单例** | `allowed_builtin_tools` 在 `chat_node` 中按列表过滤，不动 registry 本身 |
| **LangGraph `stream_mode` 多值** | 直接加 `'metadata'` 一个值，无需新接口 |
| **NestJS `HttpService`** | 调 LangSmith REST 复用，无需引入新 HTTP 客户端 |
| **AsyncLocalStorage**（Node.js 内置） | trace_id 上下文跨 Service / DAO 透传，无新依赖 |

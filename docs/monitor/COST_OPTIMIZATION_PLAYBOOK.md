## 2. 候选优化项

> **候选项 1 — RAG 检索结果数量调优**
> - **现状成本**：高成本 trace 主要落在知识/RAG 场景。
> - **改进方案**：在 `packages/agent/src/rag/retriever.py` 将 `top_k` 下调（如 5→3），并加相似度阈值过滤。
> - **预期降本**：$1.5 ~ $2.1/月。
> - **实施工作量**：S
> - **风险**：召回下降导致回答完整性下降。
> - **回滚策略**：恢复原 `top_k`，并用 `pnpm eval:run -- --dataset rag --baseline <实施前实验名>` 校验。

### 候选 2 — 系统提示词瘦身

- **现状成本**：全量请求都承担固定系统提示开销。
- **改进方案**：在 `packages/agent/src/graph/nodes.py` 抽取并压缩系统提示；仅在 `retrieved_memories` 非空时注入记忆段。
- **预期降本**：$0.6 ~ $1.1/月。
- **实施工作量**：S
- **风险**：指令压缩可能造成风格和稳定性波动。
- **回滚策略**：恢复旧 prompt 文本并对比 baseline。

### 候选 3 — 短消息走更便宜模型

- **现状成本**：`Pro/deepseek-ai/DeepSeek-V3.2` token 占比 100.00%，缺少低复杂度分流。
- **改进方案**：在 `packages/agent/src/graph/nodes.py` 增加短消息路由分支，引入 `.env` 变量 `OPENAI_MODEL_SHORT`。
- **预期降本**：$0.7 ~ $1.3/月。
- **实施工作量**：M
- **风险**：回答风格不一致，可能引入质量波动。
- **回滚策略**：移除路由分支或将短模型改回主模型。

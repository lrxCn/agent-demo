## 4. §6 第一步 4 个澄清的最终决策

> 决策依据：项目持有人 2026-05-13 跳过澄清问题 → 取每个问题的"【推荐】"选项 + 已读代码现状交叉验证。

### 4.1 trace_id 全链路传递方式（澄清问题 1 + 3 合并）

- **前端 → 后端**：前端在 `packages/frontend/src/api/request.ts` 拦截器中生成 W3C `traceparent` header（`00-<32 字符 trace_id>-<16 字符 span_id>-01`），注入到 `POST /api/v1/agent/chat` 等所有 API 请求。
- **后端 → Agent**：NestJS 新增全局 `TraceInterceptor`（`packages/backend/src/common/interceptors/trace.interceptor.ts`），从 header 解出 `trace_id`，挂到 AsyncLocalStorage 中；`agent.service.ts` 调 LangGraph 时把 `trace_id` 一并写入 `input.metadata.app_trace_id`。
- **Agent → LangSmith**：在 `packages/agent/src/graph/nodes.py` 的 `chat_node` 入口取出 `state['metadata']['app_trace_id']`，通过 `langsmith.run_helpers.get_current_run_tree().add_metadata({'app_trace_id': ...})` 打到 LangSmith trace 的 metadata。
- **后端 → 前端（回流 langsmith_run_id）**：后端在 SSE 流的**第一帧**推送新 payload 类型 `{type:'trace', trace_id, langsmith_run_id}`，前端 `useChat.ts` 收到后存到当前 message 对象上，作为后续 👎 反馈推送 LangSmith Dataset 的关联键。

> **决策依据**：W3C 标准（§8 决策 #10）；浏览器 fetch 流可读 SSE data 但 EventSource 不能读 header，选 SSE data 路径兼容性最好。

### 4.2 TTFT 埋点起点

- **前端 TTFT (`t_user_ttft`)**：在 `useChat.ts` 中，用户按下回车（`sendMessage` 调用瞬间）`performance.now()` 记 `t0`；收到第一条 `{type:'token'}` SSE 时记 `t1`，差值打印到 `console.debug`。
- **后端 TTFT (`t_server_ttft`)**：NestJS `agent.controller.ts` 拿到请求时记 `t0`；`streamChat` 第一次 `yield {type:'token'}` 时记 `t1`，写入结构化日志的 `extra.ttft_ms` 字段，由 LangSmith 自动 trace 体现在 `chat_node` 的 first-token 上（无需自上报）。
- **看板口径**：LangSmith 看板使用 `t_server_ttft`（统一服务端口径），`t_user_ttft` 仅前端 console 用于排查"慢是网络还是服务"。

### 4.3 LangGraph 启动方式 + `LANGCHAIN_PROJECT` 配置位置

- **开发期统一命令**：`uv run langgraph dev --port 8123`（与 `.env` 中 `LANGGRAPH_API_URL=http://localhost:8123` 对齐，覆盖 `langgraph dev` 默认 2024 端口）。
- **`LANGCHAIN_PROJECT` 读取位置**：仅在 Agent 进程读取，由 `packages/agent/src/config/settings.py` 通过 `python-dotenv` 加载 `../../.env` 即可。`.env.example` 默认值 `LANGCHAIN_PROJECT=plan2code-agent`，开发者可改本地名（如 `plan2code-zhang3-dev`）实现多人不串。
- **后端 / 前端**：不读取 `LANGCHAIN_PROJECT`，因为 trace 上报由 Agent 进程内 LangChain SDK 自动完成。
- **生产环境**：v1 范围**不涉及**。

### 4.4 从 LangGraph SSE 取 `langsmith_run_id` 的实现路径

- 修改 `packages/backend/src/agent/agent.service.ts` 的 `streamChat` body：

```ts
stream_mode: ['messages-tuple', 'updates', 'metadata']
```

- 新增 `extractFromMetadata(payload, ...)` 方法解析 LangGraph metadata 事件，从中取出顶层 `run_id`。
- 新增 SSE payload 联合分支：

```ts
| { type: 'trace'; trace_id: string; langsmith_run_id: string }
```

- 在 `streamChat` 取到 `run_id` 的第一时间 `yield` 一次 `{type:'trace', ...}`（保证它在第一帧的 token 之前到达前端）。
- 前端 `useChat.ts` 在 SSE 解析分支中识别 `trace` 类型，挂到当前 assistant message 的 `meta.langsmith_run_id` 字段。

## 5. 五大目标的可勾选验收清单

> **格式约定**：每条以 `⬜` 开头，对应 `prompts/` 中的一个具体步骤。`PROGRESS.md` 中会复用这套清单做接力棒。

### 5.1 目标 1 — 可观测性看板（Observability Dashboard）

#### 5.1.1 LangSmith 启用与项目命名

- ⬜ `.env` 已设置 `LANGCHAIN_TRACING_V2=true` 且 `LANGSMITH_API_KEY` 非空（人工核对）
- ⬜ `LANGCHAIN_PROJECT` 改为可识别的本地名（推荐 `plan2code-<dev>-<env>`，如 `plan2code-local-dev`）
- ⬜ Agent 启动后能在 LangSmith Web 网页 → Projects 列表里看到该 project 名

#### 5.1.2 自动 trace 验证

- ⬜ 触发一次完整对话（含工具调用），LangSmith 上能看到 trace
- ⬜ trace 内能看到节点 span：`chat_node` / `tool_node_with_retry` / `fallback_node`（命名与 `nodes.py` 一致）
- ⬜ 每个 span 有 `latency`、`input`、`output`、`error`（如有）

#### 5.1.3 metadata / tags 切片维度

- ⬜ 在 `chat_node` 入口手动打 metadata：`mem0_user_id`、`thread_id`、`app_trace_id`、`role_ids`（取自 state）
- ⬜ 用户在前端 👍 / 👎 时，后端把 `feedback:up` / `feedback:down` 作为 tag 写到对应 run（通过 LangSmith API 的 `client.create_feedback` 或 `update_run`）
- ⬜ LangSmith UI 上能按 `metadata.mem0_user_id="<某用户>"` 过滤、按 `tag:feedback:down` 过滤
- ⬜ LangSmith 上 token 用量按 model 维度可见（前置依赖：5.5.1 Models 单价配置）

#### 5.1.4 业务指标可见性

- ⬜ 单次对话端到端延迟、`t_server_ttft`、tool call 平均耗时 → 在 LangSmith trace 详情页可见
- ⬜ 错误率（按节点）→ LangSmith Project 概览卡片可见
- ⬜ token 用量按 user / 按 tag 切分 → LangSmith Dashboards 自定义图表可保存

### 5.2 目标 2 — 全链路 Trace（前端 → 后端 → Agent）

#### 5.2.1 前端 trace 注入

- ⬜ `packages/frontend/src/api/request.ts` axios 拦截器自动注入 `traceparent` header（每次请求生成新 trace_id）
- ⬜ `packages/frontend/src/composables/useChat.ts` 的 SSE fetch 也手动注入 `traceparent` header
- ⬜ 前端 `console.debug` 日志包含本次请求的 `trace_id`，可与浏览器 Network 面板对应

#### 5.2.2 后端 trace 拦截器 + 结构化日志

- ⬜ 新建 `packages/backend/src/common/interceptors/trace.interceptor.ts`，全局注册（`AppModule.providers`）
- ⬜ 新建 `packages/backend/src/common/middleware/structured-log.middleware.ts`，输出 JSON 结构化日志，字段：`trace_id`、`user_id`、`thread_id`、`module`、`level`、`msg`、`elapsed_ms`、`extra`
- ⬜ 替换 `agent.service.ts` 中所有 `this.logger.xxx(...)` 为带 `trace_id` 的结构化 log（通过 AsyncLocalStorage 取）
- ⬜ 后端 stdout 日志中能 grep 到同一 `trace_id` 跨多行（NestJS 默认 logger 改成 JSON formatter）

#### 5.2.3 Agent trace 透传 + 主动打 metadata

- ⬜ `packages/agent/src/graph/state.py` 在 `AgentState` 中新增 `app_trace_id: str` 字段（可选，默认空串）

- ⬜ `chat_node` 入口调用 LangSmith helper 把 `app_trace_id` 打到当前 run 的 metadata
- ⬜ 在 LangSmith UI 搜索 `metadata.app_trace_id="<前端生成的 trace_id>"` 能精准定位到 trace

#### 5.2.4 trace_id 回流前端

- ⬜ `agent.service.ts` `streamChat` body 加 `'metadata'` 到 `stream_mode`
- ⬜ 新增 `extractFromMetadata` 解析方法 + `{type:'trace', trace_id, langsmith_run_id}` payload 类型
- ⬜ 该 SSE 帧在第一个 `token` 帧之前到达前端
- ⬜ `useChat.ts` 把 `langsmith_run_id` 挂到当前 message 的 `meta` 字段
- ⬜ 前端任意一条 AI 消息可以右键 / 调试面板看到 `langsmith_run_id`

#### 5.2.5 端到端验证场景

- ⬜ **正常路径**：前端 console 看到 `trace_id=abc...` → 后端 stdout 同 `trace_id` → LangSmith trace metadata 同 `trace_id` → 三端一一对应

### 5.4 目标 4 — Agent 边界 & 安全限制

> **顺序锁死**（来自 §8 决策 #9）：token 配额 → 工具白名单 → prompt-injection 关键词初筛 → 输出 PII / 敏感词扫描 → 审计日志落库。

#### 5.4.1 step-1：token 配额

- ⬜ 新建 `packages/backend/src/common/quota/quota.service.ts`，用 Redis 存 `quota:{user_id}:{date}` 字段：`prompt_tokens` / `completion_tokens` / `total_tokens`
- ⬜ 配置外置：`packages/backend/src/common/quota/quota.config.ts` 读 `.env`：`QUOTA_DAILY_TOKENS_PER_USER=200000` `QUOTA_PER_THREAD=50000`
- ⬜ `agent.controller.ts` 在调 `chatStream` 前先调 `quota.checkAndReserve(user_id)`，超限抛 `429`
- ⬜ SSE 流结束时由 `agent.service.ts` 从 LangGraph 最后一帧 `metadata` 中取 `usage` 写回 `quota.commit(user_id, tokens)`
- ⬜ `.env.example` 同步新增上述配额变量
- ⬜ 配额耗尽时前端聊天气泡显示降级提示："今日 AI 用量已达上限，请明日再试"

#### 5.4.2 step-2：工具白名单（按角色）

- ⬜ 数据存现有 `permissions` 表，新增权限组 `agent:tool:*`（如 `agent:tool:search_knowledge_base` `agent:tool:search_my_calls`）
- ⬜ `agent.service.ts` 在调 LangGraph 之前根据 `user.permissions` 计算 `allowed_builtin_tools` 列表，写入 `input.allowed_builtin_tools`
- ⬜ `packages/agent/src/graph/state.py` 新增 `allowed_builtin_tools: list[str]` 字段
- ⬜ `packages/agent/src/graph/nodes.py` `chat_node` 在拼 `tools` 时按该列表过滤 builtin 工具（前端工具白名单已有，不动）
- ⬜ 测试：用一个无 `agent:tool:search_knowledge_base` 权限的角色登录，对话中要求"搜知识库"，Agent 不应能调用该工具

## 6. 全局非功能需求

| 类型 | 要求 |
|---|---|
| **性能** | 监控埋点单独开销 < 单次请求延迟 5%（LangSmith 自动 trace 是异步上报，可忽略；自研 guardrails 同步执行，每个 filter < 50ms） |
| **可用性** | LangSmith Cloud 不可达时，Agent 仍能正常回复（LangChain SDK 默认捕获上报异常） |
| **配置外置** | 所有阈值（配额、超时、采样率、黑名单文件路径）走 `.env` 或 `*.yaml`，不硬编码 |
| **国际化** | 中文注释 + 中文用户提示；LangSmith Web UI 是英文，文档不翻译其字段名 |
| **可测试性** | 每个 guardrails filter 必须有单元测试（pytest），覆盖正例 / 命中 / 边界 |
| **安全** | `INTERNAL_API_KEY` 不入库、不打日志；LangSmith API key 仅在 Agent 进程使用 |
| **文档同步** | 任何契约变更必须同步更新 `docs/API_CONTRACTS.md` 与 `docs/ARCHITECTURE_FOR_AI.md` |

## 10. 风险与降级策略

| 风险 | 触发条件 | 降级策略 |
|---|---|---|
| LangSmith Cloud 网络不通 | 中国大陆出境受限 | LangChain SDK 默认 fail-silent，Agent 仍正常工作；监控暂时缺失，开发者切 VPN 或使用 LangSmith 设置中的 Asia 区域 endpoint |
| LangSmith 配额耗尽（免费版每月 5k traces） | 日常开发 + 大规模 eval | 在 `.env` 临时设 `LANGCHAIN_TRACING_V2=false` 关闭上报，或升级到付费版 |
| 配额检查导致正常用户被误伤 | 配额阈值过低 | `.env` 提高 `QUOTA_DAILY_TOKENS_PER_USER` 即可，无需改代码 |
| 关键词黑名单误杀正常请求 | 用户输入巧合命中 | v1 黑名单**仅警告不拒绝**（参见 5.4.3）；事后从审计日志中分析误报率 |
| `traceparent` header 被中间件 / CDN 剥离 | 反向代理过滤 | 后端发现缺失时自动 fallback 生成新 trace_id，记录 `extra.trace_origin=backend` 用于排查 |
| `langsmith_run_id` 在 SSE 中缺失 | LangGraph metadata 事件未及时到达 | 前端 fallback 用 `trace_id` 作 LangSmith Dataset 关联键，仍可查到（可能需要更长检索时间） |
